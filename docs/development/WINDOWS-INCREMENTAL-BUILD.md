# Windows incremental build consistency

## Report and diagnosis

The user reported a crash after starting the September 6, 20:04:49 executable.
The 20:06:29 minidump records an access violation while reading a colour from
an invalid pointer. Unwinding the saved frame pointers identifies chat formatting
called by chat reception, whose caller is the event-notice dispatch path.
That path passes an EventMessage, not a ChatMessage; interpreting the former
as the latter reads unrelated memory as a seat pointer.

The 20:08:51 executable still has the mismatch: ODClient's event dispatch calls
virtual slot 0x88, while GameMode's table puts chat reception there and its
event-notice override at 0x90; the same caller matches the editor's older table.
The binary inspection fails for game mode and passes for editor mode, showing
incompatible object layouts within one linked executable. Camera work added a virtual base-class method,
but the incremental build produced incompatible callers and tables. The build
uses deprecated MSVC minimal rebuild (`/Gm`) with shared compiler state; rebuilding
only changed source files did not restore a consistent layout.

Microsoft documents that this deprecated option can miss required rebuilds after
header changes and stores class dependency information in a project-wide IDB
file; disabling it removes that unreliable dependency decision from future
builds ([MSVC minimal rebuild documentation](https://learn.microsoft.com/en-us/cpp/build/reference/gm-enable-minimal-rebuild?view=msvc-170)).
The binary mismatch is directly verified; the compiler's internal sequence of
cache decisions was not recorded.

The original public map was stale and was rejected. An isolated relink produced
a map whose code section matches the saved 20:08 executable byte-for-byte; that
file was built after the actual crash and must not be presented as the exact
crashing binary. Dump instruction bytes and saved frame pointers, plus the
independently inspected later caller/table mismatch, provide the diagnosis.

## Targeted build correction

Explicitly disable deprecated MSVC minimal rebuild (`/Gm-`) in the Windows
Release/Debug compiler flags and rebuild the complete Release target. This leaves the hand, camera,
chat and event behavior intact and avoids reusing class-layout state from that
obsolete compiler feature. Runtime preparation is required after regeneration.
No game is launched or terminated by the assistant.

Work branch: `fix/windows-incremental-build`, based on merge `e1276f81`, preserving
`fix/hand-tool-grip` checkpoint `9beb2ba8`, camera checkpoint `8c1410c3` and
subsequent parallel work.
The shared checkout and normal index remain untouched.

minimal rebuild disabled in every generated Visual Studio configuration.

relink whose code section matches the prepared executable byte-for-byte.
